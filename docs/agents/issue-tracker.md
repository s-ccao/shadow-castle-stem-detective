# Issue tracker: GitHub

Issues and specs for this repository live as GitHub Issues in `s-ccao/shadow-castle-stem-detective`.

## Conventions

- **Create an issue:** use GitHub Issues with a clear title, a concise problem statement, reproduction steps when relevant, and an acceptance checklist.
- **Read an issue:** include its comments and labels before proposing or implementing a change.
- **List issues:** filter by open/closed state and triage labels as appropriate.
- **Comment on an issue:** record decisions, verification results, blockers, and handoff context.
- **Apply or remove labels:** use the mappings in [`triage-labels.md`](triage-labels.md).
- **Close an issue:** only after the relevant change has been verified; leave a short closing summary.

When the GitHub CLI is installed, run its issue commands from this clone so it infers the repository from `origin`. Until then, use the GitHub web interface for the same operations.

## Pull requests as a triage surface

**PRs as a request surface: no.**

External pull requests are reviewed as code contributions, not treated as feature requests in the triage queue.

## When a skill says "publish to the issue tracker"

Create a GitHub issue in this repository.

## When a skill says "fetch the relevant ticket"

Read the issue, including comments and labels, before acting.
