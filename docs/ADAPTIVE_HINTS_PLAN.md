# Adaptive NPC Guidance in an Educational Detective Game

> **Evaluation is governed by [`docs/EVALUATION_PROTOCOL.md`](EVALUATION_PROTOCOL.md)**,
> which is frozen at protocol version `heldout-v1`. Where this plan and the
> protocol disagree, the protocol wins.

A research project built **inside** *Shadow Castle: STEM Detective*, not beside
it.

## Research questions

**Primary — an education question:**

> Can an adaptive NPC hint system use a player's demonstrated knowledge to
> reduce redundant guidance while preserving useful puzzle assistance?

**Secondary — an AI systems question:**

> As interaction history grows, can structured retrieval maintain hint quality
> while using less context, latency and cost than full-history prompting?

## What is deliberately *not* claimed

The game's own paper states that formal evaluation of learning outcomes has not
been conducted. Nothing here changes that. Reducing redundant guidance is a
claim about **hint quality**; it is not a claim about learning. Those are
different studies, and the second needs human participants this project does not
have.

## Conditions

| Condition | What it is | Model? |
|---|---|---|
| **A — static** | The shipped hint system, unchanged | no |
| **B — rule-based adaptive** | Deterministic selection from player state | no |
| **C1 — LLM full history** | Whole event history in the prompt | yes |
| **C2 — LLM retrieval** | Relevant events only | yes |

Condition B exists so that C has to beat something real. If a handful of rules
already removes the redundancy, **that is the finding**, and it should be
reported rather than hidden. "When is an LLM actually worth it?" is a better
question than "is the LLM good?"

### Condition C selects; it does not write

The LLM chooses among **authored** hints and returns a decision, not prose:

```json
{ "should_hint": true, "hint_id": "h_butler_knows_rule",
  "reason": "player holds dual_lock_rule", "confidence": 0.84 }
```

This is safer (the castle is played by children at
`play.shadowcastledetective.com`), testable, automatically scorable, and cannot
hallucinate. It also means no model ships in the public web build.

## The technical core

The audit relocated the problem. It is not that NPCs lack memory — it is that
the game has **no unified model of what the player knows**.

"Demonstrated knowledge" is scattered across three stores with different
semantics: `knowledge_items` (one concept), `story_flags` (the other ten, plus
progression), and `evidence_items` (what the player is carrying). No component
reads across them, so every NPC branch tests the one store it happens to know
about — evidence — and none tests understanding.

So redundant guidance is not a stochastic model failure to be patched with a
memory system. It is a **structural consequence of missing epistemic state**.
The contribution is therefore:

> a unified **Player Knowledge Model** over the game's existing stores, and an
> evaluation of what different guidance policies can do once it exists.

That framing also explains why Condition B can work at all without a model, and
sets up the honest question for Condition C: *given* a knowledge model, what
does an LLM add?

## Two classes of scenario — never conflated

| Class | What it is | Status |
|---|---|---|
| **Reachability-validated synthetic** | States generated by accumulating real prerequisites, proven reachable against `REACHABILITY_RULES` | 72 exist |
| **Observed playtest** | Extracted from real human play sessions | **none yet** |

Synthetic states are legitimate evidence that a state combination is *possible*
under the game's logic. They are **not** evidence that a player ever reached it,
and must never be described as playtest-derived.

## Metrics

| Metric | Asks | Why it is needed |
|---|---|---|
| **RedundantHintRate** | Did the NPC re-teach something already demonstrated? | Primary |
| **Coverage** | Did the system say anything at all? | **Guards the obvious cheat**: a system that stays silent scores 0% redundancy |
| **RelevantHintRate** | Was the hint one a good NPC could have given? | Guards against "not redundant but useless" |
| **RepetitionRate** | Did it repeat itself? | Distinct from redundancy |
| **StateViolationRate** | Did the hint contradict the state it landed in? | Guards against saying something *false* |

Coverage exists because of a specific failure mode: **B could have won on
redundancy simply by saying less.** It does not — coverage is 100% for both
conditions — but that had to be measured, not assumed.

`StateViolationRate` counts hints delivered where their own declared
preconditions do not hold — an NPC telling a player it has not seen the stain
the player is holding. Both conditions score 0%.

**That zero was verified rather than trusted.** A metric that can never fire
reports a perfect score while measuring nothing, which is a failure this project
has already made once (see the lessons log). Probing
`state_violations()` directly confirms it detects both a missing-evidence and a
missing-concept delivery, and stays clean on a correct one.

`RelevantHintRate` is scored against **hand-assigned** ground truth
(`VALID_HINTS`), deliberately not derived from the selector's own rules.
Deriving it from the logic under test would only prove the system agrees with
itself.

## Scenario schema

Every hand-written scenario carries its own provenance:

```
id, npc, room
knowledge_items, story_flags, evidence_items
reachability_basis: [ the player actions that produce this state ]
```

The validator proves a state combination is *legal*; `reachability_basis`
records how a player actually gets there. Both are asserted by the harness, so
neither field can rot as scenarios are added — a scenario without a basis fails
the run.

**Hand-written table — 20 audited states, hand-annotated ground truth:**

| metric | A static | B adaptive |
|---|---|---|
| RedundantHintRate | 20.0% | **0.0%** |
| RepetitionRate | 40.0% | 20.0% |
| Coverage | 100.0% | **100.0%** |
| RelevantHintRate | 55.0% | **100.0%** |
| StateViolationRate | 0.0% | **0.0%** |

### Why the 100% is weak evidence, and what it cost

That figure went 80% → 100% after one change, and it should be read with
suspicion rather than satisfaction.

**The circularity is real.** The same person wrote `VALID_HINTS` and then
changed the selector until it matched. A system agreeing with annotations its
author wrote is a **consistency check**, not validation. The number would only
become evidence under independent annotation or playtest data, and neither
exists yet.

**What was actually wrong.** Printing the four misses showed a single pattern:
all four were states where the player had demonstrated a concept, a line written
for exactly that concept existed, and the selector delivered a generic line
anyway. The cause was that Rule 2 was gated on the shipped line being
*redundant* — and a generic line like `h_gardener_no_evidence` teaches nothing,
so it is never redundant. Anti-redundancy had been implemented as a proxy for
adaptivity, and the proxy was strictly narrower than the goal.

The fix is defensible on its own terms — an adaptive system should prefer a line
conditioned on what the player has demonstrated — but it was still *found by*
the ground truth, so it does not independently confirm it.

**It cost something.** On the 72-state synthetic sweep, repetition got
**worse**: 41.7% → 45.8%. Preferring the targeted line more often means
delivering the same targeted line more often. Redundancy stayed at 0% and
relevance improved, so the trade looks worth it — but it is a trade, and the
regression is reported rather than buried.

**Reproducible remaining figures:**

**Reachability-validated synthetic sweep — 72 states:**

| metric | A static | B adaptive |
|---|---|---|
| RedundantHintRate | 25.0% | **0.0%** |
| RepetitionRate | 47.2% | 45.8% |

### Read this before quoting the numbers

- **Coverage is the load-bearing control.** Both conditions speak in every
  state, so B's redundancy gain is real rather than bought with silence. Without
  this column the headline would be unsupportable.
- **Relevance of 100% is a consistency check, not a result** — see the section
  above. Independent annotation or playtest data would be needed to make it
  evidence.
- **The larger set corrected the repetition claim, twice.** On 20 hand-written
  states B appeared to halve repetition (40% → 20%). Across 72 synthetic states
  the improvement was **5.5 points** (47.2% → 41.7%) — and after the Rule 2 fix
  it shrank again to **1.4 points** (47.2% → 45.8%). The redundancy result has
  held throughout; the repetition result has moved every time the sample or the
  selector changed. Quote the sweep, and treat repetition as the weak claim.
- Condition A's redundancy comes from **one shipped line**. The audit found it
  is the only shipped line carrying a teachable concept, so the ceiling is
  genuinely small.
- Condition B reaches 0% using **three hints authored by this project**. The
  game ships no knowledge-conditioned hint at all. Declared new content,
  reported separately, never presented as pre-existing behaviour.

### Every state is checked for reachability

A scenario describing a save file no player can produce measures nothing.
`AdaptiveHintData.REACHABILITY_RULES` encodes where the game actually sets each
piece of state, and the harness asserts every scenario against it.

This was not theoretical: **the validator failed 16 times across 9 of the 20
hand-written scenarios** on first run. Nearly half the table was unreachable.
The metrics did not move once fixed, because the missing flags feed no hint
condition — the correction was necessary for validity, not for the numbers.

## Player Knowledge Model v1

A read-only interpretation layer, [`scripts/player_knowledge_model.gd`](../scripts/player_knowledge_model.gd).
Nothing is stored: every value is derived on demand from `story_flags` /
`evidence_items`, so there is no new save field, no migration, and deleting the
file would change no gameplay. Nothing calls it yet.

### What DEMONSTRATED means — read before quoting any result

> **PKM v1's `DEMONSTRATED` state is an operational game-state proxy based on
> successful completion of an existing comprehension check. It is not a
> validated measure of educational mastery.**

It does **not** mean first-attempt correctness, independent mastery, validated
learning, or long-term retention.

### States

| State | Meaning |
|---|---|
| `UNSEEN` | no recorded contact |
| `LEARNING` | encountered or filed, but the check was not completed |
| `DEMONSTRATED` | the game's designated comprehension check was completed |
| `ASSISTED` | **reserved, currently unreachable** |

`ASSISTED` is produced by nothing. No challenge in the project writes state on
a wrong answer, and no hint/fail-forward path records itself. Inferring it from
existing flags would be inventing data.

### Two conflations that an audit removed

**Chemistry.** An earlier draft mapped `butler_challenge_complete` and
`chemistry_change_sorted` to one concept. The authored content differs: the
Butler asks a single question about a single stain
(`chemistry_room.gd:1540`), while the sorting tray states its own rule —
*"A change is chemical only when a new substance appears"* (`:456`) — and
applies it to 16 samples. They are now `indicator_reaction` and
`physical_chemical_change`.

**Circuit.** An earlier draft accepted *any* `circuit_bench_*_cleared` as
`current_resistance`. The three benches carry distinct titles and lesson sets
(`circuit_lab_ui.gd:2172-2177`): continuity is conduction, regulation is
resistance/voltage, fault isolation is a search strategy. Accepting any one
would report a demonstration the player may never have made. The
`current_resistance` concept was **removed rather than renamed**;
`circuit_regulation` is the check that actually exists.

### Deliberate exclusions

- **`door_*_unlocked`** — written only on a correct answer, but retry is
  unlimited and unlogged (`game_world.gd:5646-5670`), so it cannot separate
  understanding from persistence.
- **`knowledge_items`** — dead state. Its only writer sits in
  `show_circuit_learning_note()` (`game_world.gd:5717`), which has zero callers
  since commit `505f008`.
- **Evidence possession** — never produces `DEMONSTRATED`.

### Documented limitations of v1

1. **Unlimited retries everywhere.** No check counts attempts.
2. **Fixed content, zero randomization.** A repo-wide grep for
   `shuffle|randi|randf|pick_random` across every challenge returns no matches.
3. **Most checks reveal the rule on failure** — sorting prints the authored
   `why_en` (`change_sorting_minigame.gd:367`); library failure messages state
   the rule (`:352`, `:365`, `:372`); the circuit lesson is permanently on
   screen (`circuit_lab_ui.gd:2180`).
4. **Brute-force is tractable** — 4 options (Butler), 6 permutations (red),
   8 combinations (green), 21 attempts (blue).
5. **No raw observations are recorded anywhere** — no attempts, timings, or
   assistance markers exist in the project.

These are documented limitations of the shipped game, not defects this project
redesigns.

## Future work — validated learning outcomes

A separate research question, deliberately **frozen** and not implemented here:
*does the player independently understand the concept after learning?* Answering
it would require, at minimum:

- first-pass diagnostic tracking
- a learning → reassessment loop
- randomized question and option order
- anti-memorization question pools (chemistry currently has 16 items, **0
  spare**, and items already repeat within one playthrough)
- raw assessment history rather than a derived enum
- `ASSISTED → DEMONSTRATED` transitions
- formal learning-outcome evaluation with human participants

None of this is in scope. PKM v1 makes no claim about learning outcomes.

## Two audit findings that shaped the design

**Knowledge lives in two places.** Only `current_resistance` reaches
`GameState.knowledge_items`; the library's three concepts are recorded as story
flags. A selector reading `knowledge_items` alone would see one concept out of
eleven.

**The shipped system never reads knowledge.** All three NPC branches test
evidence. The state that would prevent redundant guidance is tracked and never
consulted — so redundancy is structural, not accidental.
